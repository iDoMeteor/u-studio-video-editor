# Bug audit, 2026-09-20

Read-only audit of `main` at `ba2d011` (v0.4.0): every file under `src/core`,
`src/engine`, `src/app`, `src/render`, plus the test names in `tests/`.
Nothing was changed. Findings are ordered by severity within each section;
each one names the file and line, how it shows up for a user, and a fix
sketch. "Verified" means a standalone repro was run against the installed
MLT 7.40 (`mlt++-7`) on this machine; "by inspection" means confirmed by
reading the code path end to end. No sanitizer or valgrind was available on
the machine, so the memory-lifetime item (E1) is by inspection only.

## Engine

### E1. `reset()` destroys the profile the running consumer's tractor still uses (High, by inspection)

[engine_sync.cpp:57-63](../../src/engine/engine_sync.cpp#L57) calls
`applyProfile()` first, which does `m_profile = makeProfileFrom(...)`
([engine_sync.cpp:91](../../src/engine/engine_sync.cpp#L91)) and so runs
`Mlt::Profile::~Profile` on the old profile immediately. `mlt_profile_close`
frees the struct. Every producer, playlist and the tractor built by the
previous `rebuildAll()` hold a raw `mlt_profile` pointer to it, and that
tractor is still connected to the running consumer inside
`PlaybackController` until `rebuildAll()` finishes and `rebuilt` fires
`setTractor()`, which is the first thing that stops the consumer.

Between those two points the consumer's read-ahead thread keeps calling
`get_frame` on the old tractor (it does so even at speed 0), which reads
fps/width/height from freed memory. The window is the whole of
`rebuildAll()`, which opens a producer for every asset in the loaded
project, so it is long for a real project.

Triggered by Open Project and by Recover. Ordinary edits are not affected
only because of E2 (the consumer is stopped before the old tractor is
dropped, and those rebuilds don't touch the profile).

Fix: make `reset()` stop the consumer before replacing the profile. The
cleanest shape is a `EngineSync::resetting` signal (or a
`PlaybackController::detach()` call) fired at the top of `reset()`, or have
`reset()` keep the old profile alive in a local until after `rebuilt` has
been emitted. Also note the `Mlt::Profile` the *consumer* was built from is
a leaked clone (E7), which is the only reason the consumer itself survives.

### E2. The hot-swap branch in `setTractor()` can never be taken (High, verified)

[playback_controller.cpp:105](../../src/engine/playback_controller.cpp#L105)
compares `tractor->profile()` to the pointer saved from an earlier
`tractor.profile()` call
([playback_controller.cpp:47](../../src/engine/playback_controller.cpp#L47)).
In mlt++ 7.40 `Mlt::Service::profile()` returns a *new* heap wrapper around
a *clone* of the service's profile on every call (verified: two calls on
the same tractor gave different wrapper addresses and different
`get_profile()` pointers; `libmlt++-7.so` imports `mlt_profile_clone`). The
comparison is therefore always false, so every `setTractor()` goes down the
`shutdown()` + `selectAndStartConsumer()` path.

User-visible consequences:

- Every edit, including every tick of the track-volume slider (each tick
  is a `SetTrackVolume` command, each command a `rebuildAll()`), stops and
  restarts `sdl2_audio`. That is an audio-device close/open per edit and a
  main-thread block on `consumer->stop()`.
- The log gets an `[engine] Playback consumer: sdl2_audio` line at info
  level per edit.
- The class comment's promise ("editing never clicks or drops the audio
  device") does not hold.

Fix: compare the underlying `mlt_profile` (`tractor->get_profile()`), or
better, compare the profile *values* (width, height, fps, sar), since
`EngineSync::reset()` allocates a new profile even when its contents are
unchanged. Delete or stop leaking the wrappers (E7).

### E3. A still image extended past its imported length plays shorter than the timeline shows (Medium, verified)

`masterProducerFor()`
([engine_sync.cpp:130](../../src/engine/engine_sync.cpp#L130)) bumps the
still's `length` once, at first use, to `asset.info.lengthInSequenceFrames`,
which is set at import and never updated. A cut is clamped to its parent's
length (verified: a `colour:` producer at default length 15000 cut to
`(0, 20000)` came back as `out=14999`, `playtime=15000`; after
`set("length", 30000)` the same cut was 20001 frames). So once the user
drags the still's right edge past whichever is larger of 15000 frames and
the import length, the model says N frames but the playlist entry is
shorter, and every following clip on that track starts early in MLT
relative to where the timeline draws it. `EngineSync::verify()` would flag
it, but the app never calls it. The same clamp applies to the saved XML
played by `melt`, since the writer emits the producer with
`out = lengthInSequenceFrames - 1` and no `length` property.

The owner's use case (hour-long livestream edits, 108k frames at 30 fps)
crosses the 15000-frame default within the first eight minutes of timeline.

Fix: in `rebuildTrackPlaylist()` (or `masterProducerFor()`) raise the
still's `length`/`out` to the max `clip.out + 1` over every clip that
references the asset before taking cuts, and write the same `length`
property in the XML producer. Alternatively update
`lengthInSequenceFrames` on resize for boundless assets.

### E4. Loop wrap applies while paused (Medium, by inspection)

[playback_controller.cpp:340](../../src/engine/playback_controller.cpp#L340)
checks `position >= loopOut` on every delivered frame with no `m_playing`
guard. Paused refresh frames (after `seek()`, `stepFrame()`, `toEnd()`,
timeline clicks) go through the same path, so with a loop set the user
cannot place the playhead at or after loop-out: it snaps to loop-in. `End`
and clicking past the loop are the obvious triggers.

Fix: guard with `m_playing.load()` (and arguably `m_speed > 0`, since a
reverse shuttle should not wrap forward either).

### E5. Waveforms use a hard-coded `atsc_1080p_30` profile (Low-Med, by inspection)

[waveform_cache.cpp:74](../../src/engine/waveform_cache.cpp#L74). Peaks are
computed one per *30 fps* frame over `[in, out]` in *sequence* frames, so
for any project profile other than 30 fps the envelope is drawn at the
wrong time scale and covers the wrong source range. Latent today because
`Model::createEmpty()` defaults to 30 fps, but a loaded project carries its
own profile. Also at line 106 the warning lacks the `[waveform]` prefix.
Fix: pass the sequence profile (or its fps) into the job.

### E6. Curated module directory under `/tmp` (Low)

[factory_policy.cpp:66-77](../../src/engine/factory_policy.cpp#L66). When
`XDG_RUNTIME_DIR` is unset, the symlink farm that MLT will `dlopen` from is
created at a predictable world-writable path
`/tmp/ustudio-mlt-modules-<pid>` after a `remove_all`. Another local user
can pre-create it. Low because it only affects headless/CI runs, but the
directory should be created with `mkdtemp` semantics. Also the post-loop
`if (ec)` at line 118 reuses the `ec` from the last `create_symlink`, so a
single failed symlink is misreported as a scan error and discards the whole
curated dir.

### E7. Leaked wrappers (Low, verified)

`tractor.profile()` at
[playback_controller.cpp:47](../../src/engine/playback_controller.cpp#L47),
`tractor->profile()` at line 96, and twice per call at line 254 each
allocate a cloned `Mlt::Profile` that is never deleted. `verify()`'s
`m_tractor->track(i)` ([engine_sync.cpp:256](../../src/engine/engine_sync.cpp#L256))
leaks a `Producer` wrapper per track (test path only). Small, but line 254
runs on every play/pause/scale change.

## Core

### C1. Negative `in` on boundless assets (Medium, verified)

`ResizeClip::apply` only rejects `newIn < 0` for bounded assets
([primitives.cpp:249](../../src/core/commands/primitives.cpp#L249)), and
`InsertClip` does the same at line 164. `Model::check()` invariant 3 also
skips boundless assets. Dragging a still's left edge left of its start
(app_window.cpp:1145 computes `newIn = clip.in + delta`) therefore lands a
clip with `in < 0`. MLT clamps the cut's `in` to 0 (verified:
`cut(-5, 100)` gave `in=0`, 101 frames where the model expects 106), so the
playlist entry is shorter than the model and later clips on the track drift
earlier. Fix: reject `in < 0` unconditionally in both commands and in
`check()`.

### C2. Merged commands defeat the clean point (Low-Med, by inspection)

[undo_stack.cpp:14](../../src/core/commands/undo_stack.cpp#L14) merges into
the top entry *after* `setCleanPoint()` may have marked that depth as
saved. Sequence: drag track volume, Save, drag the same track's volume
again. The second drag merges into the saved command, `isClean()` stays
true, the title shows no dirty mark and the autosave heartbeat skips it.
Fix: refuse to merge when `m_undo.size() == m_cleanDepth`.

### C3. Loader trusts untrusted input (Low, by inspection)

`reader.cpp` never runs `Model::check()` on the result, and the app does
not either. Consequences of a hand-edited or truncated file:

- `frame_rate_den = 0` ([reader.cpp:304](../../src/core/xml/reader.cpp#L304))
  reaches `Mlt::Profile::set_frame_rate(num, 0)` and every fps division.
- A missing `ustudio:next_id` defaults to 1
  ([reader.cpp:316](../../src/core/xml/reader.cpp#L316)); the next
  allocated id collides with an existing track/clip id and
  `unordered_map::emplace` silently fails in `insertClip`, leaving a track
  with a duplicate id in `clips`.
- `clip.in > clip.out`, overlapping entries, or unknown track kinds are
  accepted as-is.
- `parseMarkersJson` indexes `json[pos]` after two unchecked `++pos` steps
  (a marker object with no `:`), which can read past the end.

Fix: run `check()` after load and refuse on any problem; validate
`fps.den > 0` and `nextId > max id`.

### C4. Signal lifetime hazards (Low, by inspection)

`EngineSync` subscribes in its constructor
([engine_sync.cpp:67](../../src/engine/engine_sync.cpp#L67)) and never
disconnects. Any `EngineSync` that dies before its `Model` leaves a dangling
`this` in the model's slot list; the next edit is a use-after-free.
`renderProject()` constructs one on a stack copy so production is safe
today, but only by accident of call site. Related: `Model` is copyable and
movable with `changed` included, so `snapshot = m_model`
(app_window.cpp:560) copies the live EngineSync's slot into the render
thread's model, and `m_model = std::move(*loaded)` (app_window.cpp:503,
1525) silently drops every subscriber, which `reset()` then papers over
for exactly one of them. Fix: store the connection id and disconnect in
`~EngineSync`; make `Signal` non-copyable so `Model`'s copy/move must
handle it explicitly.

### C5. Undo of a split loses the fade-out (Low, by inspection)

`Model::splitClip` resets `left.fadeOut`
([model.cpp:318](../../src/core/model/model.cpp#L318)) but
`SplitClip::revert` restores only `out`. Latent until fades are editable.
Also `insertClip` emits `ClipInserted` for the right half before its
flags/effects are copied (lines 320-327), so a non-batched listener sees
an intermediate state and `EngineSync` rebuilds twice per split.

## App

### A1. Undo/redo buttons and dirty marker are stale after edits (Medium, by inspection)

`updateWindowTitle()` is the only place that sets the undo/redo button
sensitivity and the "•" dirty mark
([app_window.cpp:1411-1417](../../src/app/app_window.cpp#L1411)), and it is
called only from the constructor, Save, Open, Undo, Redo and Recover. After
an import, split, move, trim, delete, add/remove track, lock, or volume
change nothing calls it. In practice: start the app, import a clip, and the
Undo button stays greyed out (Ctrl+Z still works because the action is
always enabled); the title never shows the dirty mark until the first
undo/redo. Fix: connect `m_undoStack.changed` to `updateWindowTitle()` once
in the constructor and drop the manual calls.

### A2. Recovery leaves the project "clean" and deletes the only copy (Medium, by inspection)

The recovery path ([app_window.cpp:1525-1549](../../src/app/app_window.cpp#L1525))
calls `m_undoStack.clear()`, which resets `m_cleanDepth` to 0 on an empty
stack, so `isClean()` is true. The comment says the intent is the opposite.
Effects: no dirty mark, the heartbeat autosave returns early because
`isClean()`, focus-loss autosave likewise, and lines 1548-1549 have just
deleted the autosave and its meta. A crash after recovery and before a
manual Save loses the recovered work again. Fix: give `UndoStack` a way to
mark the current depth dirty (e.g. `setCleanPoint(SIZE_MAX)` or a separate
`m_forceDirty` flag), and delete the autosave only after a successful
manual Save to a real path.

### A3. "Close gap" closes only part of the gap (Medium, by inspection)

`m_contextMenuGapStartFrame` is the frame under the cursor, and
`onCloseGapClicked` uses it as the gap start
([app_window.cpp:917](../../src/app/app_window.cpp#L917)). Right-clicking in
the middle of a gap moves the following clips left by
`nextClip.position - clickedFrame`, leaving the part of the gap before the
click. The delete message ("Right-click the gap to close it") sets the
expectation that the whole gap closes. Fix: compute the gap start as the
previous clip's `end()` (or 0) on that track in `onTimelineRightClicked`.

### A4. Video clips on audio tracks (Medium, by inspection)

Import inserts onto whatever `m_activeTrack` is
([app_window.cpp:427](../../src/app/app_window.cpp#L427)), and a clip drag
can drop on any row ([app_window.cpp:1137](../../src/app/app_window.cpp#L1137)).
Neither `InsertClip` nor `MoveClip` looks at `Track::kind`, so a video clip
lands on an audio track with `videoEnabled = true`, violating invariant 8
of `Model::check()`. Because audio tracks sit at the bottom of the MLT
stack, its picture shows through wherever the video tracks have gaps. Fix:
have the commands (or the app) call `setClipEnabled(video=false)` when the
destination is an audio track, and refuse moving a video-only clip onto one.

### A5. A second instance offers and then deletes the first instance's autosave (Low, by inspection)

`offerRecoveryIfAny()` runs at startup and `findRecoverable()` returns any
autosave newer than its target, including one a still-running instance
wrote minutes ago. Whatever the user answers, lines 1548-1549 delete it.
Fix: write the owning pid (or a lock file) into the meta and skip entries
whose owner is alive.

### A6. Output paths can be source media; render is not atomic (Low, by inspection)

`onRenderFinished` passes the chosen path straight to `avformat`, and
`saveProject` writes `path + ".tmp"` then renames over `path`. Neither
refuses a path that is one of the project's assets, contrary to the
"never overwrite a user's source media" rule in CLAUDE.md, and the render
is written in place rather than temp-file + rename. Fix: check the chosen
path against the bin, and render to `<path>.part` then rename.

### A7. Focused sliders swallow transport keys (Low, by inspection)

`m_seekScale` was made non-focusable for this reason, but `m_volumeScale`,
`m_trackVolumeScale` and the preview-scale dropdown are still focusable, so
after clicking one of them Left/Right/Home/End move the widget instead of
the playhead. Fix: `gtk_widget_set_focusable(FALSE)` on those, or move the
accelerators to a capture-phase shortcut controller on the window.

## Things checked and found sound

- Command apply/revert symmetry for every primitive, including reuse of ids
  on redo and `RemoveTrack`'s clip capture.
- `Transaction` and `CompositeCommand` rollback ordering and batch
  bracketing; `EngineSync` batch depth handling.
- `MainThreadDispatcher` lifetime token and the `g_idle_add_full` choice;
  `PlaybackController::shutdown()`'s frame-show fence.
- `WaveformCache` queue/quit handshake.
- XML round-trip of blanks, entries, and `std::to_chars`/`from_chars`
  locale independence.
- `FactoryPolicy` init/close ordering relative to the GTK shutdown hook.
