# Upstream repros

Standalone reproductions of bugs we found in libraries we use, one folder
per report: `<project>/<slug>/`. Each is a `melt` script or a short C
program against the library alone, with no code from this project. Its
header comment names what it shows, the expected and actual results, and
the build and run lines. Inputs are generated by the script or by the
`ffmpeg` line in the header; no media is committed. Run them in a scratch
directory.

The reports themselves, with their issue links and status, are in
[MLT upstream reports](../../docs/developer/notes/mlt-upstream.md) and
[GTK and libadwaita upstream reports](../../docs/developer/notes/gtk-upstream.md).
A GNOME report that's written but not yet filed is the `REPORT.md` in its
folder, ready to paste into GNOME's GitLab (GTK's Bug template).

On Fedora, `melt` is installed as `melt-7`: run the scripts with
`MELT=melt-7`. The C programs build with
`cc <file>.c $(pkg-config --cflags --libs mlt-framework-7)`, plus
`-pthread` or `-lEGL` where the header says so; the GTK ones with
`pkg-config gtk4` or `libadwaita-1`. The AT-SPI probes run on a private
Xvfb, D-Bus session and AT-SPI bus through `atspi-harness.sh
<probe.py> <program> [args]`, so nothing shows on the desktop.
